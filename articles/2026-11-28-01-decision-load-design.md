**利用者に届く成果が増え、必要な能力・品質・安全性を保ちながら総管理負荷が減った状態を、組織エントロピーの反転と定義する。** エージェントの追加を検討する前に、成果と負担の比較条件を決める。

私が開発するKafstylerでは、案件と知識が増えても読む量と重複運用を増やさないことを成功条件にしている。この定義と以下の観測手順は著者の提案であり、査読で確立された理論・規格ではない。

## 1. 問題：仕事が増えることと、人間の負担が減ることは違う

Cuiら (2026) は3社の開発者4,867人を対象にした無作為化実験の統合分析で、AIコーディング支援によって完了タスク数が26.08%増えたと報告した（標準誤差10.3%）[1]。

一方、Narayanan & Feigh (2026) の80人を対象とする監督実験では、AIエージェント間に依存関係がある条件で人間の作業負荷が増えた。情報の抽象度を変えてもその増加は解消されなかった [2]。

異なる実験の結果である。実行時の生産性の上昇だけでは、管理負荷の減少は分からない。

## 2. 中心命題：成長の条件に総管理負荷を含める

[KafstylerのMISSION](https://github.com/KAFKA2306/kafstyler/blob/007137cb1ba50aa1c1d5409b935a8e7616c252f6/MISSION.md)では、利用者に成果を届けること、担当AIが変わっても再開できること、差分のない保守でLLMを起動しないことを成功条件に置く。

必要な成果・品質・安全性を維持した上で、成果と能力が増えても総管理負荷を増やさない。さらに減少させることを目標とする。これはKafstylerの価値判断であり、あらゆる組織で達成できるという経験則ではない。

## 3. 定義：何を成長と負荷として扱うか

| 項目 | 本稿の定義 |
| --- | --- |
| 成果 | 利用者の入口で利用できる仕事の結果 |
| 能力 | 必要な品質・安全性で実行可能な仕事の範囲 |
| 規模 | 案件数、利用者数、仕事量など、対象に応じて固定する指標 |
| 管理負荷 | 人間の探索・判断・調整・監督・引き継ぎ・維持に使う時間と関連費用 |

能力の拡大は成果件数とは別に記述する。既存の能力を失うことによる負荷削減は認めない。単位当たりの負荷の減少は効率化として区別する。ここでいうエントロピーは熱力学的な量ではない。

## 4. 仕組み：処理能力より先に処理需要を見る

Galbraith (1974) は、情報処理能力を増やす方法と処理の必要性を減らす方法を区別した。自己完結的な仕事単位や余裕資源は後者に当たるが、資源の重複や費用との比較が必要になる [3]。

Kimら (2026) は3系統のLLM、6種類のベンチマークにまたがる260構成について、同じプロンプト・ツール・計算予算で単一エージェントと4種類の複数構成を比較した。単一エージェントの基礎性能は協調の利点を説明する重要な要因だった [4]。

処理能力を増やす設計と、調整の必要性を減らす設計を別の候補として比較する。複数構成が常に劣るという結論ではない。

## 5. 測定：総負荷と成果当たり負荷を併記する

次の観測項目は提案仕様である。

| 指標 | 単位・条件 |
| --- | --- |
| 利用可能な成果 | 同じ種類・受入条件の完了件数 |
| 能力 | 対応可能な業務の範囲と各受入条件 |
| 総管理時間 | 人時間／観測期間 |
| 成果当たり管理時間 | 人時間／完了件数 |
| 運用費用 | 円／観測期間 |
| 品質・安全 | 業務固有の既存基準、失敗・手戻り |

異質な成果は種類ごとに比較する。時間と金額は独立した指標とし、換算根拠なしに加算しない。成果件数がゼロなら成果当たり時間は定義しない。

| 観測結果 | 判定 |
| --- | --- |
| 成果増加・総管理時間減少・運用費用非増加 | 反転 |
| 成果増加・総管理時間一定・運用費用非増加 | 負荷非増加 |
| 成果当たり時間減少・総管理時間増加 | 効率化。反転ではない |
| 管理時間減少・運用費用増加 | トレードオフ。反転とは判定しない |
| 能力・品質・安全の低下、負担の転嫁 | 反転と認めない |
| 判定に必要な観測値不足・比較条件不一致 | 判定不能 |

最初に能力・品質・安全・負担転嫁の条件を適用する。その条件を満たした場合に、成果・時間・費用を比較する。時間と費用の一方が悪化する場合は単一の総合点で相殺しない。この分類は著者が採用する保守的な判定仕様である。

## 6. 実践：比較対象と成功条件を先に決める

1. 成果、能力、必須条件、組織の範囲、観測期間を決める。
2. 既存の業務履歴と利用先から、変更前の成果と管理負荷を把握する。
3. エージェントを追加する案と、既存構成を活用する案を比較する。
4. 同じ仕事の種類・受入条件で変更前後を観測する。繁忙期や仕事の難易度が異なる場合は分けて扱う。
5. 第2部で負荷の発生源を特定し、第3部の介入後に同じ指標へ戻る。

### 効果の再現性を上げる比較方法

ソフトウェア工学の実験方法を論じたKitchenham & Madeyski (2024) は、同等の課題・条件で複数回比較し、参加者の技能差をランダム割付やブロック化で扱う方法を整理している [7]。以下はその考え方を本稿の設計判断に適用する提案である。

- 介入前に、対象業務、主要な評価項目、意味のある改善幅、観測期間、品質・安全・費用の許容条件を定める。結果を見て成功条件を変えない。
- 旧構成を対照とし、同じ種類・難易度の独立した仕事に新旧構成を割り当てる。可能なら仕事の種類や担当者の技能で分けた上でランダムに割り当てる。順次導入しかできなければ、同時期の未変更業務と繁忙度・モデル変更などを記録する。
- モデルの版、入力、ツール、権限、計算予算、終了条件を固定する。複数要素を同時に変えた場合は、個別の要素の効果としない。人間や別エージェントによる救済も計上する。
- 成功例だけでなく失敗、再試行、未完了を含める。仕事ごとの結果とばらつきを残し、同じ手順を独立した業務・担当・環境で繰り返す。異なる条件の結果を平均して隠さない。

小規模な比較は方向性を知る材料であり、統計的な有意差がないことを同等性の証明にしない。観測できなかった値は未測定とする。研究目的の比較を日常運用の新たな承認工程にせず、既存の業務履歴で足りるなら新しい台帳を作らない。

## 7. 根拠：協業と意思決定に関する実測

Dell’Acquaら (2026) はP&Gの専門職791人を対象とする商品開発課題の実験で、AIを利用する個人がAIなしの2人チームに匹敵する成果を出したと報告した [5]。Josephら (2026) の病院の電子カルテ導入研究では、意思決定の分散とチーム内の共通理解との関連が報告された [6]。

いずれも人間の協業の研究であり、自律エージェント組織の総管理負荷を直接測った結果ではない。

参照実装として、Kafstylerの[作業規約](https://github.com/KAFKA2306/kafstyler/blob/007137cb1ba50aa1c1d5409b935a8e7616c252f6/AGENTS.md)は、目的をMISSION、仕事をIssue、実装をGit、成果を利用先に分離している。この分担は公開された設計上の事実であり、負荷反転の実測結果ではない。

具体的には、実行契約の入口は[変更前](https://github.com/KAFKA2306/kafstyler/blob/bc5d2cc801a364bf580d86de441d7754903762e3/COMMANDS.md)の209行から[変更後](https://github.com/KAFKA2306/kafstyler/blob/25afa7800567fdd5321502ccf730d12816c27212/COMMANDS.md)の36行へ変更された。詳細は知識、エージェント、開発、制作の4領域へ分離されている。行数は取得した本文の末尾空白を除き、改行で分割した値である。

この差から分かるのは入口の構造と行数の変化までである。文書全体の総量、人間の読解時間、成果件数、運用費用の変化は未測定である。従って、この事例の反転判定は「判定不能」となる。入口が短くなったことを組織の成長と取り違えない。

## 8. 反証条件：仕事を減らしただけでは成功としない

成果や必要な能力が失われた、品質や安全性が低下した、別の担当者や利用者へ負担を移した場合は反転と判定しない。

成果が増えても総管理負荷が増えたなら、成果当たりの負荷が改善していても反転は未達である。比較条件がそろわない場合は判定を保留する。

## 9. 標準仕様案：同じ条件で結果を引き継ぐ

入力：対象業務と組織の境界、比較対象、観測期間、成果の受入条件、維持すべき能力・品質・安全条件。

出力：成果量、能力、総管理時間、成果当たり時間、運用費用、品質・安全性、判定、出典、未測定項目。期間・対象・単位を各値に対応させる。再現のために介入前後の版、対象の識別子、比較条件、除外理由、実測値の出典を既存の履歴から参照できるようにする。

第2部へ渡すのは、この観測条件と既存の業務履歴である。業務固有の成果単位は置き換えられるが、他分野での有効性は未実証である。
