「学ぶコストは下がった。でも、差は開いている。」

記事一覧にこの一文が出てきたら、「何と何の、何の差？」と聞きたくなります。AIの性能の差なのか、使った人の理解度の差なのか。書き手には分かっていることが、題を短くしたときに抜けています。

この例を挙げたいる科さんは、省いた文脈を戻し、伝えたいことに順位を付けてから、題を書き直す手順を紹介しています。そこに一つ足すなら、できた題だけを別の会話に渡して「何の話だと思う？」と聞くことです。本文を先に渡すと、題から抜けた情報まで拾えてしまいます。 [いる科さんの投稿](https://x.com/iru_cection/status/2121705510319825086) · [投稿のミラー](https://teapawt.org/iru_cection/status/2121705510319825086)

## 「何の差か」と「差が広がったか」を確かめる

ここからは架空の原稿で試します。無料版と有料版のAIを使って同じ教材を学び、学習直後のテストの点数を比べたとします。テストは一度です。

| 検査用の見出し | 読み取れる内容 | 判定 |
| --- | --- | --- |
| 学ぶコストは下がった。でも、差は開いている。 | 比較対象と指標が確定しない | 対象・指標を明示する |
| 無料版と有料版のAIで、理解度の差が広がった | 比較対象、指標、差の拡大 | 差の拡大には複数時点の証拠が要る |
| 無料版と有料版のAIで、学習直後の理解度を比較した | 比較対象、指標、測定時点 | 採用 |

二つ目は、題を読むだけで何を比べたか分かります。でも「広がった」と言うには、以前の差と今回の差を同じ測り方で比べる必要があります。今回の原稿で言えるのは、三つ目の「比較した」までです。

## 何を残すか決めてから短くする

1. 本文を渡します。スライドなら台本も添え、「何を比べ、何を測ったか」を文字数を気にせず一文にします。推測で補った箇所があれば、原稿で確認できる箇所と見分けられるようにします。
2. 原稿に複数の話があるなら、AIに題に残す優先度を1〜10で付けてもらい、理由と該当箇所も出してもらいます。AIが学ぶ手間の話を一番に選び、書き手は理解度の比較を見せたいなら、ここで順位を入れ替えます。定型の原稿なら、冒頭の目的文を判断に使えます。
3. 主題を一つ選んで題を書きます。結果を載せる記事なら表の三つ目、これから比較を始めるスライドなら「無料版と有料版のAIで、学習直後の理解度はどう違うか」と書けます。
4. 原稿を渡していない別の会話に、読者と同じ情報を見せます。記事一覧なら題だけ、図と並ぶスライドなら図のラベルも添えます。「何を比べ、何を測る話か」を聞き、書き手の意図と合うか確かめます。最後に、題の言い切り方を原稿の証拠と照合します。 [W3Cの見出し解説](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) · [Assertion–Evidence](https://www.assertion-evidence.com/)

## 編集の判断を、採用条件に変える

表の三つの見出しを、判定に使う項目だけにすると次のようになります。比較対象と指標が読めない場合と、「広がった」を支える時点数が足りない場合で、jqが別の結果を返します。

```bash
jq -nc '
  inputs
  | {
      id,
      result: (
        if .subject_and_metric_recovered == false then "missing_comparison"
        elif .claims_widening and (.evidence_timepoints < 2) then "missing_time_series"
        elif .claims_widening then "check_trend"
        else "accept"
        end
      )
    }
' <<'EOF'
{"id":"ambiguous","subject_and_metric_recovered":false,"claims_widening":true,"evidence_timepoints":1}
{"id":"overclaim","subject_and_metric_recovered":true,"claims_widening":true,"evidence_timepoints":1}
{"id":"supported","subject_and_metric_recovered":true,"claims_widening":false,"evidence_timepoints":1}
EOF
```

二時点以上なら `check_trend` になります。照合では対象の定義と測り方を確かめ、実際に差が大きくなっていれば採用します。

原稿をまとめて処理するなら、値の照合と集計をjqに任せます。モデルには、題を作る回は原稿、初見で読み取る回は表示文言、根拠を照合する回は該当箇所を渡します。採用した一案を標準出力に出し、保留の理由と根拠の位置はJSONLに残します。

2026年公開版を使うなら、生成・評価とJSON出力はPromptfoo 0.125.1、結果の受け渡しと集計はjq 1.8.2に任せられます。用意するのは、媒体ごとの判定項目、対照例、両者をつなぐ短いスクリプトです。 [Promptfooリリース](https://github.com/promptfoo/promptfoo/releases/tag/0.125.1) · [評価結果の出力仕様](https://www.promptfoo.dev/docs/configuration/outputs/) · [jqのリリース記録](https://github.com/jqlang/jq/releases/tag/jq-1.8.2)

## 自動化したら、何を見逃したか数える

「短くして」とだけ頼む場合を基準に、同じ原稿と表示条件で比べます。採用済みの題から比較対象だけを削る、指標だけを変える、問いだけを断定に変える。このように一か所ずつ変えると、どの誤りを見逃したか分かります。判定方法の調整に使った原稿は、本番の比較から外します。 [評価設計の公式ガイド](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

- **伝わったか。** 題から読み取った主題が原稿と合う割合を出します。比較を扱う題では対象と指標も照合します。順位付けの時点で背景が主題になったのか、題に縮めたときに抜けたのかも記録します。モデルで測る値は、読者理解の推定値です。
- **言いすぎを通したか。** 原稿を超える断定や因果、「差が広がった」のような時系列の主張を採用した件数を数えます。対照例では0件を合格条件にします。
- **採用に何トークン使ったか。** 採用率と、生成・判定・やり直しに使った総トークンを採用件数で割った値を出します。意味が伝わる割合と採用率が基準を下回らない構成の中から、採用1件あたりのトークンが最も少ないものを選びます。
