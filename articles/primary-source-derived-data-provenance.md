集計表の件数が856から7,699に変わった。約9倍だ。取引が急増したのか、以前の計算に誤りがあったのか。

どちらとも限らない。集計した資料の範囲が変われば、現実に何も起きていなくても数字は変わる。

**集計値の増減を現実の変化として解釈する前に、集計対象と計算方法をそろえよ。** そろえられないなら、増減の解釈を保留する。

## 856と7,699は何を数えたのか

2026年8月11日に保存した米国政府倫理局（OGE）の取引開示資料の[集計記録](https://github.com/KAFKA2306/investor2/blob/c8a3ab271b58396c2aa3b38d9ba7a8f4244a3210/docs/research/data/us_oge_trump_278t_trade_count_2026-08-11.json)には、以前の856行が一部の提出資料だけを対象とした値だったと記録されている。

| 項目 | 以前の集計 | 8月11日の集計 |
| --- | --- | --- |
| 取引開示行数 | 856 | 7,699 |
| 対象資料 | 一部の提出資料 | 17文書を索引化 |
| 内訳 | この記録からは復元できない | 購入5,026、売却2,673 |
| 集計の出所 | 以前の部分集計 | 外部集計結果との照合 |

後者の取引日の範囲は外部集計によれば2025年1月1日から2026年5月29日、索引上の最新提出日は2026年7月1日である。

[OGEの公式ガイド](https://www.oge.gov/web/278eGuide.nsf/Form_278-T)は取引報告書の対象を定義している。OGEが7,699という単一の合計を公表したわけではない。7,699は開示された取引の行数に関する派生値であり、本人が直接注文した回数を示すものでもない。

差の6,843行は計算できる。しかし、その差を新たに発生した取引数とは呼べない。以前の資料集合を復元できなければ、同じ範囲でどれだけ増えたかは分からないからだ。

## 足し算が合っていても、増減の説明は成立しない

仮に、ある工場で月別の不良数を集計しているとする。

| 月 | Aライン | Bライン | 報告値 |
| --- | ---: | ---: | ---: |
| 4月 | 10 | 集計対象外 | 10 |
| 5月 | 10 | 20 | 30 |

この例は説明用の仮定である。報告値は3倍だが、比較できるAラインの不良数は変わっていない。Bラインの4月の数が分からない以上、工場全体の不良数が増えたかどうかも分からない。

ここで必要なのは、より精密な足し算ではない。新旧の対象を一致させることである。

対象を追加したのか、現実の件数が増えたのか、計算方法を変えたのか。この三つは同じ差分に現れるが、必要な対処は異なる。

## 数字の意味を、数字と一緒に渡す

8月11日の記録には、数値だけでなく資料の索引、観測時刻、外部集計の出所が残されている。次はその記録から主要項目を抜き出したものだ。

```json
{
  "observed_at": "2026-08-11T14:13:00+09:00",
  "scope": {
    "oge_278t_document_count": 17
  },
  "aggregate": {
    "transaction_rows": 7699,
    "purchases": 5026,
    "sales": 2673,
    "status": "derived_external_parser_crosscheck",
    "source_url": "https://open-cabinet.org/officials/trump-donald-j?range=12mo"
  }
}
```

[保存された原記録](https://github.com/KAFKA2306/investor2/blob/c8a3ab271b58396c2aa3b38d9ba7a8f4244a3210/docs/research/data/us_oge_trump_278t_trade_count_2026-08-11.json)の `records` には17文書の公式URLがあり、うち5文書について末尾の取引行番号を照合した記録がある。購入と売却の合計も一致する。ただし、全17文書の全行を独立に再集計した記録ではない。資料の索引、部分的な原資料照合、外部集計は、それぞれ別の根拠である。

同じ理由で、成果物のSHA-256は保存したデータの同一性を識別できても、集計範囲や計算の正しさを保証しない。[GitHubの成果物来歴に関する説明](https://docs.github.com/en/actions/concepts/security/artifact-attestations)でも、来歴の確認と成果物自体の安全性は区別されている。

## 集計値を受け取ったときの判断順序

新旧の集計について、資料IDの一覧、対象期間、数える単位、計算方法、取得できなかった資料を並べる。

| 判明した違い | 次に行うこと |
| --- | --- |
| 同じ資料・期間・方法 | 入力値の変化、訂正、計算誤りを区別する |
| 資料が追加・除外された | 共通資料だけで比較し、範囲の変更を別に示す |
| 計算方法が変わった | 同じ入力に両方の方法を適用し、差の原因を分ける |
| 旧資料や一部資料を取得できない | 全体の増減は未確定とし、取得済みの範囲だけ示す |

集計基盤に新しい管理機構を作る必要はない。既存の集計表やデータの正本に、出所、対象範囲、計算方法、観測時刻、欠落の有無を添えれば始められる。一次資料が持つ値と、その資料を使って算出した値を区別する。

資料の範囲が同じことを既存の固定データや契約から判断できる場合、毎回一覧を複製する必要はない。比較の条件が変わらないと分かる参照先を使えばよい。

数字の変更を報告するときは、変更前と変更後の数値だけでなく、何を数えたかが変わったのかを先に伝える。そうすれば利用者は、数字の変化に対して何を調べ、何を判断すべきかを選べる。
