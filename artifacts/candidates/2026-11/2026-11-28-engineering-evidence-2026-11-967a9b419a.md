# 試作品の回数を「良くなった証拠」にしてはいけない

試作品を12回作った。次の案を使うか、前の案を残すかを考えるとき、その記録は採用理由になるだろうか。回数だけでは、何を改善しようとしたのか、どの条件をそろえたのか、どの出力が良くなったのかを判断できない。

公開履歴には、[V20のコミット](https://github.com/KAFKA2306/image2outfit/commit/d392ced5348870836a1c2014399b6b3a6dfbfe76)で「twelve-cycle skirt trial」と記録された試作が不採用になり、[V21のコミット](https://github.com/KAFKA2306/image2outfit/commit/4f979fcb3c48e804cca66307bfd78077955cfb4c)で「prototype review and mesh showcase」が記録されている。確認できるのは、試作とレビューという別のイベントが記録されたことまでだ。

両案の代表入力、変更点、評価基準、出画、採否理由は公開コミットだけでは確認できない。そのため、V21がV20より優れていたとも、12回の試作が採用判断を改善したとも言えない。

**候補を選ぶときは試行回数ではなく、同じ用途・入力・環境で、何を変えたかと何が変わったかを結びつけろ。比較条件がそろわない案は、採用せずに「未比較」と記録せよ。**

## 試行回数と採用根拠は別の仕事

試作品を増やす作業には価値がある。アイデアの幅を広げたり、失敗条件を先に見つけたりできるからだ。ただし、探索量を示す回数と、候補を採用してよいことを示す根拠は別物になる。

たとえば、案Aでは特定の画像を試し、案Bでは別の画像を試したとする。案Bの出力が良ければ、それは案の違いによるものか、入力の違いによるものか分からない。評価者や照明条件が変わった場合も同じだ。出力が変わった原因を案の変更だけに帰せない以上、優劣の比較として採用を正当化できない。

この問題の仕組みは、比較対象ではなく比較条件にある。候補ごとに次の情報が欠けると、結果は案の性能ではなく記録の欠落を示す。

| まずそろえる項目 | 欠けたとき起きること |
| --- | --- |
| 使う場面 | 良い出力の意味が案ごとに変わる |
| 入力と環境 | 出力差を案の変更だけに帰せない |
| 評価基準 | 良い・悪いの判断が主観に戻る |
| 前案からの変更点 | どの変更が結果を変えたか分からない |
| 観測結果 | 採用理由を後から作る必要がある |

V20とV21の記録では、この表を埋める十分な根拠がない。したがって、ここから導けるのは「試行回数が不十分な証拠である」ことではなく、**公開記録だけでは採用判断を支えられない**ことだ。

## 採否を決める最小の手順

次に案を比較するときは、事後的に説明を付け足すのではなく、比較前に次の一行を決める。

```text
目的：
入力：
環境：
合格基準：
変更点：
観測結果：
判断：採用 / 保留 / 降格
```

目的は「何に使う案か」、入力は「何を与えるか」、環境は「どこでどの設定で見るか」、合格基準は「どの結果なら採用するか」を表す。案ごとに目的と環境をそろえ、比較できない項目は合格基準に含めない。

たとえば、候補を選ぶ目的が「既存の衣服画像に合うメッシュを選ぶこと」だとする。入力画像、表現を見る場面、変更前後の表示条件を固定し、期待する出力を事前に決める。同じ入力で出力を観測できたときだけ優劣を判断できる。入力や環境が変わる案が混じったままなら、観測結果は参考記録に留め、採用案は保留する。

この手順は5分ほどで始められる。ただし、候補の実行自体が目的の記録、たとえば探索した組み合わせの件数なら、試行回数は採否ではなく探索量として使える。

## 適用条件と撤回条件

この規律は、複数の候補から一つを採用・棄却する場面で使える。コードの設定比較、文面の候補選定、運用手順の改善、データ分析のモデル選定にも持ち帰れる。ただし、比較の目的、入力、環境、評価基準をそろえられることが条件になる。

次の条件なら適用外、または追加検証が必要になる。

- 採否ではなく、探索の幅や作業量を測っている。
- 入力、環境、評価基準が管理できず、出力差の原因を分けられない。
- 長期運用で初めて必要な安全性、保守性、利用者反応が評価されていない。
- 単一の事例であり、同じ条件を持つ別の比較で再現していない。

また、次の観測が得られたら規律を狭めるか撤回する。

- 同じ目的と環境でも、候補間の差が観測不能になるほど測定誤差に埋もれる。
- 試行回数を増やすこと自体が優れた出力のスループットを改善し、採用判断とは独立した成果になる。
- 評価基準を固定せず探索した候補群だけで、限定的な探索成果として価値が認められる。

ここで示したのは、公開された二つのコミット履歴からは採用結果を立証できないという一つの観測と、候補比較一般へ移せる推論だ。別projectや別toolでの再現は未確認である。読者が持ち帰れるのは、候補を選ぶ前に用途、入力、環境、評価基準をそろえ、そろっていない比較を採用根拠にしない判断規律だ。
